1. 📖 Project Overview

Lara12 HRM is a comprehensive Student Management & HRM system designed for foreign study consultancy agencies. It manages the entire student lifecycle from Lead → Prospect → OnBoard → Archive, along with complete HRM (attendance, leave, salary) and double-entry accounting modules.

Key Features

👨‍🎓 Student CRM

Lead tracking, pipeline management, quotations, invoices, money receipts, document management

👥 HRM Module

Employee management, ZKTeco attendance sync, leave management, salary setup, holiday calendar

💰 Accounting

Double-entry system, Chart of Accounts (4-level grouping), Journal/Payment/Receipt/Reverse vouchers, Trial Balance, Balance Sheet, P&L

🏢 Partner Management

University/Institution partners, branch management, product/course catalog with fee structures

🔐 Access Control

Spatie role-based permissions, user banning, session tracking

📊 Reports

Attendance reports, revenue reports, student ledger, cash book, cash flow, supplier ledger

4. 🐛 Bug Report & Suggestions

🔴 Critical Bugs

BUG-01: Duplicate Route - confirmTransfer & confirmonBoard

File: routes/student.php Line 89-90

Both confirmTransfer and confirmonBoard share the same route PUT /status/transfer. The second route overwrites the first, so confirmTransfer will NEVER be called.

Route::put('/status/transfer', 'confirmTransfer');  // ❌ OVERWRITTEN
Route::put('/status/transfer', 'confirmonBoard');    // ✅ This one wins

Fix: Change onBoard route to Route::put('/status/onboard', 'confirmonBoard')

BUG-02: Race Condition in Voucher Number Generation

File: VoucherheaderController.php - All GetXxxNO() methods

Voucher number generation (GetJurnalNO, GetpaymentNO, etc.) reads lastnumber and increments it outside the DB transaction. Under concurrent requests, two users can get the SAME voucher number, causing data corruption.

// Current: Read OUTSIDE transaction, update AFTER transaction
 = ->GetJurnalNO();  // ❌ Race condition here
DB::transaction(function() { ... });
Transaction::update(['lastnumber' => ...]); // ❌ Too late

Fix: Move number generation inside DB::transaction with SELECT ... FOR UPDATE lock.

BUG-03: Wrong Relationship in Student Model - service()

File: app/Models/Student/Student.php Line 108

The service() relationship uses inverted foreign/local keys:

return ->belongsTo(StudentInService::class, 'id', 'student_id');
// ❌ This says Student.id = StudentInService.student_id but uses belongsTo
// Should be hasMany or hasOne

Fix: Change to return ->hasMany(StudentInService::class, 'student_id', 'id');

BUG-04: SearchPending checks status=0, but Pending is NULL

File: StudentController.php Line 297

The index method uses SUM(status IS NULL) as countPending but SearchPending filters with where('status', 0). These will return different results.

Fix: Use whereNull('status') instead of where('status', 0)

BUG-05: .env File Contains Production Credentials in Git

File: .env

The .env file contains real database password (Root@@Root), mail credentials (MAIL_PASSWORD), and is NOT in .gitignore properly. This is a SECURITY VULNERABILITY.

Fix: Ensure .env is in .gitignore. Rotate all exposed credentials immediately.

🟡 Medium Severity Issues

BUG-06: forceDelete() Bypasses SoftDeletes Audit Trail

Files: VoucherheaderController.php, GroupOneController.php, etc. (18+ occurrences)

Extensive use of forceDelete() on accounting records destroys audit trail permanently. Financial records should NEVER be permanently deleted.

Fix: Use soft delete or archive pattern instead. Add authorization check before any force delete.

BUG-07: Missing Authorization on Search Endpoints

File: StudentController.php - Search, SearchLead, SearchPending, etc.

All search methods lack ->authorize() checks. Any authenticated user can search ALL students regardless of role.

Fix: Add authorization checks and filter by assain_user for non-admin roles.

BUG-08: Typo in Success Messages

File: StudentController.php Lines 742, 793

"Stusent created successfully" and "Stusent update successfully" - should be "Student".

BUG-09: Student Create Loads ALL Students Unnecessarily

File: StudentController.php Line 640

'student' => Student::orderBy('id', 'desc')->get(),  // ❌ Loads ALL records

Fix: Remove this query or limit it. Create form doesn't need all student records.

BUG-10: Duplicate Route for StudentInService edit

File: routes/student.php Lines 134, 137

Route::get('/{studentInService}/edit', 'edit');            // Line 134
Route::get('{studentInService}/edit', 'editApplication');  // Line 137 - CONFLICTS!

🔵 Suggestions for Improvement

SUG-01: Add Database Indexes

Add indexes on frequently queried columns: students.phone, students.assain_user, students.status, voucherdetails.vouchernumber, voucher_balances.accountcode

SUG-02: Implement API Rate Limiting

Search endpoints return up to 500 records without rate limiting. Add throttle middleware.

SUG-03: Add Request Validation for All Update Methods

Several update methods use ->fieldname directly without Form Request validation classes.

SUG-04: Consolidate Duplicate Search Methods

Search, SearchLead, SearchPending, SearchProspect, SearchOnBoard, SearchArchive are 90% identical. Extract to a single parameterized method.

SUG-05: Add Unit & Feature Tests

The tests/ directory appears empty. Critical financial calculations need test coverage.

7. 🚀 Installation Guide

# 1. Clone Repository
git clone <repo-url> lara12hrm
cd lara12hrm

# 2. Install Dependencies
composer install
npm install

# 3. Environment Setup
cp .env.example .env
php artisan key:generate
# Edit .env with your database credentials

# 4. Database Setup
php artisan migrate --seed

# 5. Storage Link
php artisan storage:link

# 6. Run Development Server
composer run dev
# This starts: PHP server + Queue worker + Vite dev server
